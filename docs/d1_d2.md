# D1 / D2：先关闭已知存储机制，再检验数据依赖

本轮固定K32、256个物理Banks、32 GiB、128 TFLOP/s、36 MiB SRAM与相同HB预算。
不继续Peripheral Granularity DSE，也不推进Fabric或RTL。

这是冻结的D1/D2实验协议，原工作量、对照和门槛不因负结果而改变。
完成后的 [研究决策](research_decisions.md) 分开记录Research Go与Hardware Go；以下停止条件针对各自的硬件假设。

## D1

比较原时序、10%/20%的tRCD/tRAS/tRP margin假设、双Subarray overlap机制代理和历史Timing Oracle。
margin是受AL-DRAM启发的假设，不代表Mono3D可靠性验证；不同温度下的安全时序没有直接移植DDR3测量。
Oracle仍为tRAS6.5ns，明确标记理想探针。

Subarray代理保留tRAS30ns、tRP5ns与同一256物理Banks，把每个Bank的32768行分成两个16384行本地状态。
PC共享ACT/Column/Command与HB预算保持，容量不增加。
允许不同Subarrays的激活重叠，单行恢复时间不变；Column address隐式选择唯一行缓冲。
额外0.5ns首次访问选择延迟、0.15% die-area控制成本和0.01nJ/selection能量是明确的工程假设。
这接近MASA的机制代理，**不是SALP-1、SALP-2或完整MASA SA_SEL协议的复现**。
独立命令重放核查每个本地Subarray的恢复约束，另记录物理Bank的重叠活动与选择次数。

两种能量接口：

* Timing-only：沿用full-row能量与refresh/reopen代理，固定访问能量，只改变执行时序；保持旧11.44%可比性。
* Trace-driven：实际ACT/PRE/RD/WR/Refresh与打开的行缓冲关闭数量计费。
  ACT/PRE分解与系数仍为假设，不能称为器件校准；删除额外静态reopen代理，避免重复计费。

五个1 GiB full-row长轨迹、两个256 MiB partial-row控制；保留多个完整Refresh周期的稳定窗口。
已有机制基本恢复收益，或Oracle相对最优已有机制代理剩余不足5%，则停止Row-cycle新硬件方向。
若代理依赖未验证的独立Subarray条件，保留条件性结论，不宣称真实Stratum已支持SALP。

## D2

不再用平均服务率替代数据依赖。使用超过最快Tier容量的常驻权重与KV工作集，显式请求地址、
Tier、返回、任务输入、计算依赖、SRAM占用和中间结果。
比较普通Tiled双缓冲、相同缓冲预算内优化Mapping/Prefetch/Scheduling，以及只解除一个供数或执行约束的理想探针。
保持总工作量与数据移动量，分别记录missing-critical-data停顿和非关键数据返回。
包含相同Tier延迟负对照，排除通用tile/DMA收益被误称为3D特有效应。

Tier-aware时序是显式的Stratum-inspired假设，不把8个timing Tiers当作8个独立Banks或8片物理DRAM die。
若优化后的传统执行接近理想探针，则停止本轮输入join粒度的新硬件方向。
若收益同样存在于等延迟对照，则不支持其Tier特异性解释；通用执行机制的价值须单独判断。
Thermal只在执行瓶颈成立后加入，不用未经来源支持的温度/DVFS/Refresh曲线制造正结果。

### D2冻结工作量与六个对照

10个FP16 `[32768,8192]`专家投影矩阵共5GiB，前置1GiB KV扫描/归约。
所有6GiB在每次完整执行中实际读取一次，而非仅声明常驻容量。
KV阶段是2FLOP/B的受控归约代理，投影为1FLOP/B；共7GiFLOP。
它描述路由覆盖十个专家的cohort，不是一个真实token的完整Attention/LLM服务轨迹。
KV完成后才能计算投影；地址已知的投影可以预取。输入160KiB与输出640KiB驻留/广播，
KV跨Tile归约与数值softmax均为共同理想化成本，不宣称数值LLM执行验证。

256物理Banks、每Bank32768行，八个Tier各4096行；容量固定32GiB。
所有Tier共享Bank状态、ACT域、Column和HB。按论文不同tRCD与`tRAS=tRCD+27.5ns`，
保守取整到0.25ns，tRP为5ns；Tier不是独立服务通路。
命令时长直接读取冻结Ramulator序列化定义：ACT1.5CK、Column1CK、PRE0.5CK；
新增deadline与独立重放均按实际命令开始/结束偏移换算。

* ordinary_striped：64KiB任务、顺序消费、双缓冲占128KiB。
* mapped_prefetched：相同512KiB可用payload预算、4KiB任务、ready-task调度、紧凑Tier布局。
* fine_streaming_probe：相同预算、1024B任务；只放松输入join粒度。
* prefetched_striped：优化任务/预取，保持原striped布局，区分Mapping作用。
* uniform_prefetched / uniform_fine_probe：保留容量、地址与工作量，把各Tier时序设为fast，隔离非均匀延迟作用。

compact放置1GiB KV+3GiB权重到fast Tier，其余2GiB到下一Tier；不能把6GiB免费放入4GiB。
striped访问全部八Tier。普通与优化执行拥有相同硬件预算；普通仅使用双缓冲，
已有软件优化可以使用更多已存在的预取空间，不新增存储。
每Tile固定2.25MiB SRAM，payload≤512KiB，加输入/输出、最多512条请求及任务元数据仍不超过容量。
4KiB/1024B任务在每16KiB输出行内部保留部分和依赖；16Tiles计算串行各8TFLOP/s。
统一允许浮点归约重排，SRAM端口与输入广播共同理想化；没有新Fabric。
细流式probe本身可由已知分块/解耦执行实现，**不是新硬件，也不是严格全局最优性能上界**。

报告每Tile互斥周期状态：compute_busy、missing_critical_data、dependency_wait、no_remaining_work。
这不是把同时发生的DRAM限制相加成100%。另记录data-dominated task最后返回的packet字节数。
该consumer-frontier指标只覆盖任务输入join，不含Controller资源因果链，不能称为精确全局Critical-Path Data Movement。
没有独立、稳健的3D依赖信号则停止本轮执行单元设计；不能从单个负例推导所有多Tier系统均无瓶颈。

依据：[SALP §4–5](https://www.istc-cc.cmu.edu/publications/papers/2012/SALP-isca12.pdf)、
[AL-DRAM](https://arxiv.org/html/1603.08454v1)、[Stratum](https://arxiv.org/html/2510.05245v1)。
SALP-1重叠precharge/activate；SALP-2对多激活行的column访问仍有限制；MASA引入subarray selection。
AL-DRAM利用器件/温度时序裕量，与改变不同Subarray之间的操作重叠是不同机制。
