# H1–H5：执行、发现与条件性评价

本轮遵循用户更新后的路线，H4不提前指定新架构。Compute–Memory Fabric、Peripheral和Row-cycle三个既有Hardware No-Go保留。
所有计算均在Logic；DRAM在上、HB连接；无PIM、Power Delivery、多机或HBF扩展。

## 证据层次与边界

|阶段|执行与证据|不能据此声称|
|---|---|---|
|H1|冻结工作量、流量与容量下界，既有切分对照|测量性能、新HB网络|
|H2-A|原生Ramulator请求ID与命令重放，有限HB/私有SRAM/逐flit Mesh/MAC/向量执行|真实器件校准、数值LLM输出|
|H3|形状/概率生成的Decode图，packet级有限资源/生命期/依赖与资源前驱链|完整Ramulator Decode、真实路由捕获、全调度最优下界|
|H4|相对已知强基线判断剩余空间与创新边界|把Oracle或经典Tensor Parallelism改名为新硬件|
|H5|事件能量、物理位置、短token与周期RC，显式面积与功率假设|器件实测token/s、8-Tier封装复现、RTL/PPA验证|

H3有意采用更低成本的服务抽象：以D1默认26.599TB/s观测为最快full-row服务guard，以tier的bank-cycle上界限制慢tier；
**它不为每个Decode请求重放Ramulator命令。**32KiB独立返回包与64KiB计算块分离，避免单一大包人为限制并发。
同一抽象用于所有对照，结果是可审计的条件性筛选；强正信号必须回到H2级事件/命令精度验证后才可决定新硬件。

## 冻结H3场景

- Dense FFN：d1024、h4096、batch1/32，Megatron式上投影输出分片→下投影输入分片，局部GELU，无中间all-gather。
- GQA Attention：32 query heads、8 KV heads、head dimension128；batch1/context8192与batch16/context131072。
  后者真实逻辑读取8GiB KV，只有前4GiB获得fast-tier条件，其余容量条带至慢tier。Online softmax与split-KV为基线。
- MoE：80 Experts、d2048/h8192、top2，5GiB常驻权重；batch32/128。
  Uniform或Zipf1.2加权无放回路由，seed20261010，记录完整token–expert分配。
  **这些是明确分布的合成路由，不是从真实模型捕获的轨迹。**静态placement只使用期望热度，不偷看本次抽样。
  比较EP1、EP×TP4与TP16，使用配对FFN切分、共享前缀多播、普通Tile上的层次归约。
  Expert token microbatch上限16；额外microbatch重新读取权重并计费。

共同private SRAM2.25MiB/Tile：权重缓存512KiB或重分配的256KiB多缓冲FIFO、返回64KiB、收发各64KiB、
方向独立的4×4KiB packet staging、workspace1MiB、output262144B，另固定预留262144B（寄存器/输入/metadata）。
执行时检查**同时占用总量**，并非声称这些最大值均可同时静态配置。FIFO取代缓存，没有额外扩大36MiB容量。
输入包到达后才能计算，输出贡献齐备后才能归约；HB与SRAM端口、MAC、Vector、每方向32GB/s链路分别收费。
Packet staging与H2的逐flit FIFO不是同一模型，不能直接将两者绝对延迟差当成架构收益。

## 隔离与已知技术

每个图分别执行Ideal Memory、Infinite NoC、Ideal Buffer、Direct Local Streaming、Ideal Collective。
它们保持工作量/依赖与未解除资源；不是付费候选，也不是对全部调度的严格性能Oracle。
更快资源可能改变就绪顺序，故小幅非单调结果要保留，不能据此判断物理资源有负价值。
另有明确收费的既有FIFO供数与register/算子融合对照；2KiB block spill/reload的去除作为已知机制，不包装成新HB结构。
端口半/双速、链路半速仅为预设敏感性。所有点、失败与不可行项保存。

Critical Path由所选packet scheduler的依赖、资源前驱与credit释放构成，记录未归因gap。
它描述该可行执行，不证明全局最优，不把各种ideal speedup相加。

## H4与H5决策

先比较强已有方法，再判断一个理想放松是否留下值得解释的额外空间。
若明显收益来自已有Tensor Parallelism、FIFO供数或融合，则保留Research Go，并不给新硬件Hardware Go。
H4最多选择一个方向；没有剩余、可解释且具有不同物理组织的信号时，H4以“不选择新硬件”结束。
H5仍审计已知组织的面积、能量与持续运行，不虚构不存在的RTL或新架构。

H5内存能量以3.432pJ/B full-row规模为假设，分为array与logic peripheral/HB，后者不另重复计费。
MAC0.302pJ/FLOP、SRAM0.15pJ/B、Vector0.1pJ/op、NoC0.5pJ/B-hop均标明口径；后几项属于工程假设。
FIFO/steering收费0.1pJ/B、0.8mm²、0.08W，位于Logic。相同121mm²、36MiB、128TF与冷却预算。
短token采用冷启动瞬态；持续token采用实际事件能量积分后的重复周期RC，超85°C才构造uniform pacing。
等效DRAM热层、热容、peripheral物理分配与漏电/refresh反馈仍未独立校准；未提供的温度曲线关闭。

## 相关工作（原始来源）

- [Megatron-LM](https://arxiv.org/html/1909.08053v4)：配对切分是必须击败的传统执行方式。
- [Flash-Decoding](https://pytorch.org/blog/flash-decoding/)：split-KV与logsumexp合并是Attention强基线。
- [DySHARP](https://arxiv.org/html/2605.05607)：动态多播/归约和token级流水已有直接先例，不能将简单网络计算视为新贡献。
- [NetDAM](https://arxiv.org/abs/2110.14902)：启发数据通路结合，但本项目仍限制所有运算在Logic，不采用其网络级PIM设定。
- [Ma–Patterson](https://arxiv.org/abs/2601.05047)：研究方向参考，不提供本平台器件参数或实验验证。
